# Maintenance and community evidence

This is a maintenance plan, not a claim of completed tests or user adoption.

## Each release

- Review open issues and pull requests, prioritizing security, crashes, installation and export problems.
- Run the documented isolated Windows setup, unit tests and web tests; record the tested commit and results. Verify installation, live capture and export using authorized streams or test media.
- Audit dependencies and licenses; ensure no secrets, private clips, user data or provider credentials are included in release assets.
- Publish versioned release notes and checksums for verified Windows downloads.
- Keep automatic publishing opt-in and preserve creator permission checks.

## Community feedback

Use GitHub issues for reproducible bugs and feature suggestions. Ask for version, OS, steps and expected/actual behavior; redact credentials and private content. Do not solicit artificial reviews or install counts.

## Monthly evidence ledger

| Metric | Baseline as of 2026-11-28 | Evidence |
| --- | --- | --- |
| Release asset downloads | Unknown | GitHub release statistics |
| Confirmed external installs | Unknown | Voluntary reports |
| External contributors | Unknown | Merged PR history |
| User feedback | Unknown | Public issues or consented quotes |

Record dated source links and distinguish downloads from installations and unique users. Keep telemetry optional and avoid collecting identifying information.
